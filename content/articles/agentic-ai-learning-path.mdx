## 阶段 1 · 地基（Foundations）

依赖：无（从这里开始）

> 「无聊，但不可省略；跳过它们，后面全部坍塌。」（知识图谱原文）

**概念**（知识图谱）：LLM 推理；提示词模式；工具使用 / function calling；embeddings & 向量；上下文窗口

**对应的聊天系统设计**（只列图中实有的部分）：
- [D] 上下文窗口 = 固定 token 预算：系统指令 / 工具定义 / 检索块 / 旧轮次摘要 / 近期轮次 / 新消息 / 为回答预留
- [D] 提示词构建器：系统指令 + 对话历史 + 用户消息 + RAG + 工具定义（JSON）→ 模型专属格式（chat template）
- [E] 模型输出的 tool_call 只是文本：LLM 自己什么也调用不了，由编排器决定要不要执行；模型只看到工具的名称 + 描述 + schema
- [D] LLM 推理服务：prefill 一次处理整段提示词，decode 每步一个 token；每个 token 都很贵；流式让首 token 约 0.5–1 s 出现
- [F] U6 向量化：embedding 模型 → 每个文本块一个向量

**动手练习【建议】**：写一个约 200 行的命令行聊天：流式输出；接一个工具（如查货架规格表）走 function calling；按 token 预算裁剪历史：超预算先摘要或丢最早轮次，绝不丢新消息。

**完成检验【建议】**：
- [ ] 不看资料能画出上下文窗口的 7 层
- [ ] 能讲清「为什么 tool_call 只是文本」
- [ ] 历史超预算时程序不报错，新消息始终保留

## 阶段 2 · 检索与记忆（Retrieval & Memory）

依赖：阶段 1

**概念**（知识图谱）：经典 RAG；Graph RAG；Agentic RAG；短期记忆；长期记忆；情景记忆

**对应的聊天系统设计**（只列图中实有的部分）：
- [F] 索引流水线（异步）U1–U6：上传 → 对象存储 → 索引队列 → 文本提取 → 切块（~300–800 tokens）→ 向量化 → 向量库（带 ACL）
- [F] 查询（同步，几十毫秒）R1–R4：查询向量化 → 向量检索（top-k 20–50，按权限过滤，常加关键词混合）→ 重排序（~5 块）→ 上下文构建器
- [E] 数据库 / 检索连接器：把 RAG 搜索当成一个工具，由模型决定何时检索（对应 Agentic RAG）
- [C] 上下文构建器：近期轮次原文 + 旧轮次滚动摘要（短期记忆）；Redis 存热的近期轮次；G 对话摘要提前生成并存储（长期记忆的一种形态）
- [F] 检索到的文本不可信：进入提示词前先做提示词注入扫描（H）；没什么可查时跳过检索
- [—] Graph RAG、情景记忆：图中无对应

**动手练习【建议】**：用深圳两个货架项目的协议 / 图纸做一个小 RAG：切块、向量化、top-k + 重排，回答附出处；再把检索包装成工具，让模型自己决定查不查。

**完成检验【建议】**：
- [ ] 每条回答都能指出出处
- [ ] 「没什么可查」的问题会跳过检索
- [ ] 能说清短期 / 长期记忆在系统里各存在哪儿

## 阶段 3 · Agent 模式（Agent Patterns）

依赖：阶段 1、阶段 2

**概念**（知识图谱）：ReAct 循环；规划器 → 执行器；多智能体编排；上下文图遍历；工具选择与路由；反思 / 自我批评

**对应的聊天系统设计**（只列图中实有的部分）：
- [D] AI 编排器 run()：loop (max N steps) → infer → 有 tool_call 就 exec_tool 并 continue，否则 break（ReAct 形状）
- [E] 工具调用生命周期 T1–T6：一条用户消息 → 两次或更多次模型调用；每轮循环都会多一段延迟、多一个故障点
- [E] 工具执行服务：分派、超时 + 重试、写审计日志、整理结果；错误作为结果交回模型，让它恢复、换个方式重试或不用工具作答
- [D] 模型路由：按能力、套餐、成本 + 延迟选模型；工具注册表：模型只看名称 + 描述 + schema 来选工具
- [D] 编排器 worker 无状态：run 状态（步骤、已用 token、工具调用）存在 Redis，任何 worker 都能取消或恢复
- [—] 规划器 → 执行器、多智能体编排、上下文图遍历、反思：图中无对应（图中只有单一编排器；「错误交回模型重试」只是最接近反思的一点）

**动手练习【建议】**：把你的多 Bot 小队搭成「规划 Bot → 执行 Bot」：规划 Bot 拆任务，执行 Bot 按 ReAct 循环调工具，max N 步封顶；工具报错时返回错误结果，不让进程崩溃。

**完成检验【建议】**：
- [ ] 能回放一次 run 的每一步（步骤、token、工具调用）
- [ ] 人为让某个工具超时，agent 能换路完成或明确说明
- [ ] 循环不会超过 N 步

## 阶段 4 · 生产化与治理（Production & Governance）

依赖：阶段 3

**概念**（知识图谱）：置信度评分；策略闸门；审计轨迹设计；决策推理日志；评测与可观测性；成本 / token 经济

**对应的聊天系统设计**（只列图中实有的部分）：
- [H] 安全链：G1 输入审核 → G2 PII 处理 → G3 提示词注入检测 → 模型 → G4 输出审核（都是策略闸门）
- [E] 每次工具调用都要过：权限、输入校验、沙箱、超时、审计日志（谁、做了什么、参数、结果）
- [B] 便宜的检查先做：鉴权、限流（请求数 且 token 数）、校验；幂等 request_id，不二次生成、不重复计费
- [H] 故障路径：重试一次 → 熔断 → 兜底模型 → 错误事件；流式输出过 token 后绝不盲目重试
- [G] 用量 + token 统计 → 配额、计费；反馈 → 评测集、质量复核；日志 + 监控 → 告警
- [I] 可观测性：首 token 时间、tokens/s、错误率、GPU 利用率、队列深度；单条回复成本 = tokens × 模型单价
- [—] 置信度评分、决策推理日志：图中无对应（图中只有审计日志和 run 状态）

**动手练习【建议】**：给报价流水线加闸门：小偏差自动通过、大偏差转人工；每次工具调用写审计日志；每次 run 记录 token 和成本，做一张简单看板。

**完成检验【建议】**：
- [ ] 任意一份报价都能查到：谁、用了什么数据、调了什么工具、花了多少 token
- [ ] 故意弄坏主模型，系统能兜底或给出清楚的报错
- [ ] 能算出单条回复成本

## 阶段 5 · 端到端跑通一次（Trace one run end-to-end）

依赖：阶段 4

> 「你没法自上而下学会 agentic AI。要沿着依赖追溯，再看一次完整的端到端运行。」（知识图谱原文）

**概念**（知识图谱）：沿依赖关系追溯（前 4 阶段）；观察一次完整运行

**对应的聊天系统设计**（只列图中实有的部分）：
- [主线] 请求：① 客户端 → ② API 网关 → ③ 鉴权 / 限流 / 校验 / 会话 → ④ 会话服务 → ⑤ 上下文构建器 → ⑥ 模型路由 → ⑦ LLM 推理 → ⑨ 输出检查 → ⑩ 流式回客户端
- [循环] 工具循环：⑧ 编排器 ⇄ 工具执行（T1 tool_call → T2 校验 → T3 调用 → T4 结果 → T5 第二次模型调用 → T6 最终回答）
- [异步] ⑪ 回复存入消息服务 → ⑫ 发布到事件总线 → 摘要、用量计费、分析、反馈、索引、监控（不阻塞流）
- [A] 每次发送带 request_id；断线后重连按 run 查询，绝不盲目重发；stop 一路取消到 GPU

**动手练习【建议】**：向你的 agent 系统发一条需要调用工具的真实请求，用同一个 request_id 串起所有日志，画出它实际走过的 ①–⑫ 和 T1–T6。

**完成检验【建议】**：
- [ ] 能指出每一步的耗时和 token
- [ ] 中途断线重连能拿回同一次 run，不重复生成
- [ ] 能说出哪一步最慢、最贵

## 阶段 6 · 前沿（Frontier）

依赖：阶段 5、阶段 2

> 记忆反哺学习循环：这个循环区分了「会复利的 agent」和「只会重复的 agent」。（知识图谱原文）

**概念**（知识图谱）：记忆与学习循环；自我改进的 agent；多模态推理；规模化 agentic 工作流

**对应的聊天系统设计**（只列图中实有的部分）：
- [G] 反馈处理：点赞 / 点踩、举报 → 评测集、质量复核（学习循环的入口）；对话摘要提前准备，下一轮只读一行
- [D] 路由：输入含图片 / 文件 → 多模态模型
- [I] 规模化：无状态 API 与编排 worker、GPU 推理容量、队列削峰、按用户 + 按模型限流、会话库按 user_id 分片、Redis 缓存、多地域
- [G] 后台任务绝不阻塞流式输出；投递是至少一次，消费者按 event_id 去重
- [—] 自我改进的 agent：图中无对应（图中只有反馈 → 评测集，没有自动改进）

**动手练习【建议】**：把每次人工改过的报价差异写回「经验库」，下次遇到同类项目先检索这些经验；用一组固定评测集对比改进前后。

**完成检验【建议】**：
- [ ] 同类错误第二次不再出现
- [ ] 有固定评测集，能量化每次改进
