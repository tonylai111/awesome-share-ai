## 一、地基

从这里开始，前面没有要先补的阶段。

> 无聊，但不可省略。跳过它们，后面全部坍塌。

这句话来自知识图谱。这一阶段要站住的，是模型怎么推理、提示怎么写、工具怎么接。

### 概念

大模型推理，提示词模式，工具调用（function calling），向量嵌入（embeddings），以及上下文窗口。

### 对应设计

D 区把上下文窗口看成一份固定的 token 预算。里面依次放系统指令、工具定义、检索到的文本块、旧轮次的摘要、近期轮次、新消息，并给回答留出位置。

提示词构建器也在 D 区。它把系统指令、对话历史、用户消息、检索结果和工具定义拼在一起。工具定义是 JSON。拼完再转成这个模型自己的对话格式，也就是 chat template。

E 区里，模型吐出的 `tool_call` 只是一段文本。模型自己什么也调用不了，要不要执行，由编排器决定。模型能看见的，只有工具的名称、描述和 schema。

D 区的推理服务分两段。prefill 一次处理整段提示词，decode 每一步生成一个 token。每个 token 都很贵。开了流式之后，第一个 token 大约 0.5 到 1 秒出现。

F 区的 U6 是向量化。嵌入模型给每个文本块算出一个向量。

### 练习

写一个大约 200 行的命令行聊天。要有流式输出。接一个工具，比如查货架规格表，走 function calling。按 token 预算裁剪历史。超了预算，先摘要，或者丢掉最早的轮次。新消息永远留着。

### 检验

- 不看资料，能画出上下文窗口的七层。
- 能讲清为什么 `tool_call` 只是一段文本。
- 历史超预算时程序不报错，新消息始终还在。

## 二、检索与记忆

先有地基，才谈得上检索和记忆。

### 概念

经典 RAG，Graph RAG，Agentic RAG，短期记忆，长期记忆，情景记忆。

### 对应设计

F 区有一条异步的索引流水线，图上是 U1 到 U6。上传之后进对象存储，再进索引队列。然后提取文本，切成大约 300 到 800 个 token 的块，向量化，写入向量库。库带 ACL，也就是按权限隔开。

查询是同步的，几十毫秒，图上是 R1 到 R4。先把查询向量化，再做向量检索。top-k 取 20 到 50 条，按权限过滤，常常再混上关键词。然后重排，留下大约 5 块，交给上下文构建器。

E 区把数据库和检索收成连接器。RAG 搜索本身是一个工具，由模型决定什么时候查。这就是 Agentic RAG 在这张图上的落点。

C 区的上下文构建器留着近期轮次的原文，旧轮次则滚成摘要。这是短期记忆。热的近期轮次放在 Redis。G 区会提前把对话摘要算好并存下来，下一轮直接读。这是长期记忆的一种形态。

F 区还提醒，检索到的文本不可信。进提示词之前，先做提示词注入扫描，扫描在 H 区。没什么可查的时候，就跳过检索。

Graph RAG 和情景记忆，这张系统设计图里没有。

### 练习

用深圳两个货架项目的协议和图纸，做一个小 RAG。切块，向量化，top-k 之后再重排。回答要附出处。再把检索包成工具，让模型自己决定查不查。

### 检验

- 每条回答都能指出出处。
- 没什么可查的问题，会跳过检索。
- 能说清短期记忆和长期记忆各自放在系统的哪里。

## 三、Agent 模式

地基要有，检索和记忆也要有。

### 概念

ReAct 循环，规划器再到执行器，多智能体编排，上下文图遍历，工具选择与路由，以及反思和自我批评。

### 对应设计

D 区的编排器跑一个 `run()`。循环最多 N 步。每步先推理。有 `tool_call` 就执行工具，然后继续。没有就停。这个形状就是 ReAct。

E 区把一次工具调用拆成 T1 到 T6。一条用户消息，会触发两次甚至更多次模型调用。每多一轮，就多一段延迟，也多一个故障点。

工具执行服务负责分派、超时和重试、写审计日志、把结果整理好。出错时，错误当作结果交回模型。模型可以恢复，换个方式重试，或者不用工具直接回答。

模型路由也在 D 区。按能力、套餐、成本和延迟来选模型。工具注册表里，模型只看名称、描述和 schema，再决定用哪一个。

编排器的 worker 没有自己的状态。这一次 run 的步骤、已用 token、工具调用，都存在 Redis。任何一个 worker 都能取消，或者接着跑。

规划器再到执行器、多智能体编排、上下文图遍历、反思，这张图里都没有。图上只有一个编排器。把错误交回模型、让它重试，是这里最接近反思的一点。

### 练习

把你的多 Bot 小队搭成规划 Bot 再到执行 Bot。规划 Bot 拆任务。执行 Bot 按 ReAct 循环调工具，步数封顶为 N。工具报错时，把错误结果返回去，不要让进程崩溃。

### 检验

- 能回放一次 run 的每一步，包括步骤、token 和工具调用。
- 人为让某个工具超时之后，agent 能换路做完，或者把情况说清楚。
- 循环不会超过 N 步。

## 四、生产化与治理

前面的 Agent 循环能跑起来之后，才轮到上线和治理。

### 概念

置信度评分，策略闸门，审计轨迹，决策推理日志，评测和可观测性，以及成本和 token 账。

### 对应设计

H 区是一条安全链。G1 做输入审核，G2 处理个人敏感信息，图上写的是 PII。G3 检测提示词注入。然后才进模型，出来再走 G4 的输出审核。这些都是策略闸门。

E 区里，每次工具调用都要过一遍权限、输入校验、沙箱、超时和审计日志。日志记下是谁、做了什么、参数是什么、结果是什么。

B 区把便宜的检查放在前面。先鉴权，再限流，再校验。限流同时看请求次数和 token 数。请求带幂等的 `request_id`，不二次生成，也不重复计费。

故障路径也在 H 区。先重试一次，再熔断，再换兜底模型，最后记一条错误事件。流式输出已经吐出 token 之后，绝不能盲目重试。

G 区把用量和 token 统计送到配额和计费。反馈进评测集，并做质量复核。日志和监控接到告警。

I 区看的是可观测性。首 token 时间、每秒 token 数、错误率、GPU 利用率和队列深度。单条回复的成本，等于 token 数乘以模型单价。

置信度评分和决策推理日志，这张图里没有。图上只有审计日志，以及这一次 run 的状态。

### 练习

给报价流水线加闸门。偏差小的自动通过，偏差大的转人工。每次工具调用写审计日志。每次 run 记下 token 和成本，做成一张简单看板。

### 检验

- 任意一份报价都能查到是谁做的、用了什么数据、调了什么工具、花了多少 token。
- 故意弄坏主模型之后，系统能兜底，或者给出清楚的报错。
- 能算出单条回复的成本。

## 五、端到端跑通一次

生产化的闸门有了，才能把一整次运行追完。

> 你没法自上而下学会 agentic AI。要沿着依赖追溯，再看一次完整的端到端运行。

这句话来自知识图谱。概念就是两件事。沿着前四个阶段的依赖往回追，再盯着一次完整运行看完。

### 概念

沿依赖追溯，覆盖前四个阶段。然后观察一次完整运行。

### 对应设计

请求主线是这样走的。① 客户端，② API 网关，③ 鉴权、限流、校验和会话，④ 会话服务，⑤ 上下文构建器，⑥ 模型路由，⑦ 大模型推理，⑨ 输出检查，⑩ 流式回到客户端。

工具循环走 ⑧。编排器和工具执行来回交接。T1 是 `tool_call`，T2 校验，T3 真正调用，T4 拿到结果，T5 第二次叫模型，T6 给出最终回答。

异步的尾巴不挡流。⑪ 回复先存进消息服务。⑫ 再发到事件总线。摘要、用量计费、分析、反馈、索引和监控都从这里接，不阻塞正在往外流的回复。

A 区规定，每次发送都带 `request_id`。断线之后按这一次 run 去查，绝不盲目重发。用户点了停止，取消要一路传到 GPU。

### 练习

向你的 agent 发一条真的需要调用工具的请求。用同一个 `request_id` 把日志串起来。画出它实际走过的 ① 到 ⑫，以及 T1 到 T6。

### 检验

- 能指出每一步的耗时和 token。
- 中途断线再重连，拿回的是同一次 run，不会重新生成一遍。
- 能说出哪一步最慢，哪一步最贵。

## 六、前沿

端到端能追完，检索和记忆也还在。后面这条线才开始复利。

> 记忆反哺学习循环。这个循环区分了会复利的 agent，和只会重复的 agent。

这句话来自知识图谱。

### 概念

记忆与学习循环，会自我改进的 agent，多模态推理，以及规模化之后的 agentic 工作流。

### 对应设计

G 区处理反馈。点赞、点踩和举报，进入评测集，并做质量复核。这是学习循环的入口。对话摘要提前算好，下一轮只读一行。

D 区的路由会看输入里有没有图片或文件。有的话，走多模态模型。

I 区讲的是规模。API 和编排 worker 都无状态。GPU 推理要有容量。队列用来削峰。限流按用户，也按模型。会话库按 `user_id` 分片。Redis 做缓存。部署可以多地域。

后台任务绝不能堵住流式输出。投递是至少一次。消费端按 `event_id` 去重。

会自我改进的 agent，这张图里没有。图上只有反馈进评测集，没有自动改自己。

### 练习

把每次人工改过的报价差异写回经验库。下次遇到同类项目，先把这些经验检索出来。再用一组固定的评测集，对比改进前后。

### 检验

- 同类错误，第二次不再出现。
- 有一组固定的评测集，每次改进都能拿出数字。

> 你没法自上而下学会 agentic AI。要沿着依赖追溯，再看一次完整的端到端运行。
